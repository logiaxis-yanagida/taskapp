# Googleカレンダー連携 設定手順

タスク管理アプリから Googleカレンダーへ予定を自動登録するための初回設定です。所要時間は 10 分程度、費用はかかりません。

> 画面名・ボタン名は 2026年10月時点の Google Cloud Console を基準にしています。Google 側の改修で名称や配置が変わることがあります。見つからないときは、画面上部の検索ボックスに機能名（例「OAuth」「認証情報」）を入力してください。

## 全体の流れ

1. Google Cloud でプロジェクトを作る
2. Google Calendar API を有効にする
3. OAuth 同意画面（Google Auth Platform）を設定し、自分の Gmail をテストユーザーに追加する
4. OAuth クライアント ID（ウェブアプリケーション）を作成し、`http://localhost:8787` を許可する
5. クライアント ID をアプリの設定画面に貼り付けてサインインする

## 事前準備

- Google アカウント（Gmail）でログインできること
- このアプリを `起動.bat` で起動し、`http://localhost:8787/` で開けること
- ブラウザは Chrome または Edge

---

## 1. Google Cloud プロジェクトを作る

1. ブラウザで <https://console.cloud.google.com/> を開き、Google アカウントでログインします。
2. 初回は利用規約への同意画面が出るので、内容を確認して同意します。
3. 画面左上のプロジェクト名（「My First Project」など）をクリックし、「新しいプロジェクト」を選びます。
4. プロジェクト名に `taskapp` など分かりやすい名前を入れ、「作成」を押します。
5. 作成後、画面左上のプロジェクト名が今作ったものになっていることを確認します（違う場合はクリックして切り替えます）。

## 2. Google Calendar API を有効にする

1. 左上のメニュー（三本線）から「API とサービス」→「ライブラリ」を開きます。
2. 検索ボックスに `Google Calendar API` と入力し、表示された「Google Calendar API」をクリックします。
3. 「有効にする」を押します。

## 3. OAuth 同意画面を設定する

2025年以降、OAuth 同意画面は「Google Auth Platform」という画面にまとまっています。「API とサービス」→「OAuth 同意画面」を開いても、同じ画面に移動します（名称は変わることがあります）。

1. メニューから「Google Auth Platform」（または「API とサービス」→「OAuth 同意画面」）を開きます。
2. 初回は「開始」ボタンが出るので押し、次を入力します。
   - アプリ情報: アプリ名に `タスク管理`、ユーザーサポートメールに自分の Gmail
   - 対象（Audience）: **外部** を選択
   - 連絡先情報: 自分の Gmail
   - 利用規約に同意して「作成」
3. 左側の「対象」（Audience）を開き、「テストユーザー」の「Add users」（ユーザーを追加）で **自分の Gmail アドレス** を追加して保存します。
4. 公開ステータスは **「テスト」のままで構いません**。「アプリを公開」は押さないでください（押すと Google の審査が必要になります）。

### テストモードについての注意

- テストユーザーに登録したアカウントだけがサインインできます。別のアカウントで使いたい場合はテストユーザーに追加してください（最大 100 人）。
- このアプリはブラウザだけで動く方式（アクセストークンのみ、リフレッシュトークンなし）のため、サインイン状態はブラウザのタブを閉じるまでしか保持されません。**アプリを開くたびにサインインボタンを押す必要があります**（通常は 1 クリックで完了し、パスワード入力は不要です）。
- テストモードの「7 日でトークンが失効する」という Google の注意書きはリフレッシュトークンに関するもので、この方式には関係ありません。

## 4. OAuth クライアント ID を作成する

1. 「Google Auth Platform」の左側「クライアント」→「クライアントを作成」を開きます（「API とサービス」→「認証情報」→「認証情報を作成」→「OAuth クライアント ID」でも同じです）。
2. アプリケーションの種類で **「ウェブ アプリケーション」** を選びます。
3. 名前は `taskapp-local` など任意です。
4. **「承認済みの JavaScript 生成元」** の「URI を追加」を押し、次を**そのまま**入力します。
   ```
   http://localhost:8787
   ```
   - 末尾に `/` を付けないでください。
   - 「承認済みのリダイレクト URI」は **空のまま** で構いません（このアプリでは使いません）。
5. 「作成」を押すと、クライアント ID（`xxxxxxxx.apps.googleusercontent.com` の形式）が表示されます。「コピー」でクライアント ID を控えます。クライアント シークレットはこのアプリでは使いません。

## 5. アプリにクライアント ID を設定してサインインする

1. `起動.bat` をダブルクリックしてアプリを開きます（`http://localhost:8787/`）。
2. 右上の設定（歯車）を開き、「Googleカレンダー」の「クライアント ID」にコピーした値を貼り付けます。
3. 「カレンダー ID」は通常 `primary`（メインのカレンダー）のままで構いません。別のカレンダーに登録したい場合は、Googleカレンダーの「設定と共有」→「カレンダーの統合」にある「カレンダー ID」を貼り付けます。
4. 「サインイン」を押します。Google のポップアップが開くので、テストユーザーに追加したアカウントを選びます。
5. 「このアプリは Google で確認されていません」という警告が出た場合は、「続行」（または「詳細」→「タスク管理（安全ではないページ）に移動」）を選びます。自分で作ったアプリなので問題ありません。
6. 「Googleカレンダーの予定の表示と編集」への許可を求められるので「続行」を押します。
7. 設定画面に「サインイン済み」と表示されれば完了です。期限のあるタスクを追加すると、終日予定としてカレンダーに登録されます。

設定が反映されるまで数分かかることがあります。サインインに失敗する場合は、5 分ほど待ってから再度試してください。

## スマホからも使いたい場合

同じ Wi-Fi 内の PC に `http://192.168.x.x:8787` のように IP アドレスでアクセスすればアプリ自体は表示できますが、**Google のサインインはできません**。Google OAuth の「承認済みの JavaScript 生成元」には IP アドレスを登録できないためです（`localhost` だけが特別に許可されています）。

スマホでもカレンダー連携を使いたい場合は、アプリを https で公開します。

1. GitHub に無料アカウントを作り、このフォルダ一式（`index.html`、`css/`、`js/`、`docs/`）をリポジトリにアップロードします。
2. リポジトリの「Settings」→「Pages」で公開元を `main` ブランチに設定すると、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。
3. 手順 4 で作ったクライアント ID を開き、「承認済みの JavaScript 生成元」に `https://<ユーザー名>.github.io` を追加して保存します（パス部分 `/<リポジトリ名>/` は付けません）。
4. スマホのブラウザで公開 URL を開き、設定画面に同じクライアント ID を入力してサインインします。

タスクデータはブラウザごと（PC とスマホで別）に保存されます。共有したい場合は設定画面の JSON エクスポート／インポートを使ってください。公開リポジトリにはタスクデータは含まれないので、第三者に見られる心配はありません。

## よくあるエラーと対処

| 表示されるエラー | 原因 | 対処 |
| --- | --- | --- |
| `Error 400: origin_mismatch` | 「承認済みの JavaScript 生成元」にアクセス中の URL が登録されていない | 手順 4 を確認。`http://localhost:8787`（末尾 `/` なし）が登録されているか、ブラウザのアドレスが `localhost`（`127.0.0.1` ではない）かを確認。保存後は数分待つ |
| `Error 400: redirect_uri_mismatch` | リダイレクト URI 方式の設定と混ざっている、または生成元の登録漏れ | このアプリにリダイレクト URI は不要。「承認済みの JavaScript 生成元」に `http://localhost:8787` があるか確認する |
| `Error 403: access_denied`／「このアプリへのアクセスはブロックされています」 | サインインしたアカウントがテストユーザーに登録されていない | 手順 3-3 でそのアカウントの Gmail をテストユーザーに追加する。Google Workspace の組織アカウントは管理者がブロックしている場合がある |
| `403 accessNotConfigured`／「Calendar API has not been used in project」 | Google Calendar API が有効になっていない、または別プロジェクトのクライアント ID を使っている | 手順 2 で API を有効にする。画面左上のプロジェクトがクライアント ID を作ったものと同じか確認する |
| `Error 401: invalid_client` | クライアント ID の貼り間違い | `.apps.googleusercontent.com` まで含めて正しくコピーし直す |
| 「ポップアップがブロックされました」 | ブラウザがポップアップを遮断 | アドレスバー右端のポップアップブロックアイコンから `localhost:8787` を許可する |
| サインインしても次回開くと未サインインに戻る | 仕様（ブラウザセッション中のみ保持） | 「サインイン」を押し直す。1 クリックで完了する |
| 予定が登録されない（エラーは出ない） | 登録方式が「登録後に確認する」で「追加」を押していない、「手動」になっている、またはタスクに期限がない | 登録直後のトーストで「追加」を押す。常に登録したい場合は設定で「自動で登録する」を選ぶ。期限なしタスクはカレンダーに登録されない |

## 設定を取り消したい場合

- アプリ側: 設定画面で「サインアウト」し、クライアント ID を空にします。
- Google 側: <https://myaccount.google.com/permissions> で「タスク管理」のアクセス権を削除します。Google Cloud のプロジェクト自体を削除しても構いません。
